# Stable rules

运行时参数优先于 Profile，Profile 不得放宽本文件的硬约束。

## 连续性与边界

- 每条候选只能使用一个连续的 start_cue_id 到 end_cue_id；不得返回多个 source_spans、
  内部跳剪或拼接相隔内容。
- 开始和结束必须使用输入中的原始全局 cue ID；代码会从 cue 映射精确时间。
- 开头不得依赖未出现的人物、代词或前文。需要前文时向前扩展；扩展后超时则放弃或选择
  更小但完整的传播承诺。
- 结尾不得停在未回答的问题、未完成的演示或“接下来再说”。
- 在所有能完整兑现同一 viewer_promise 的合法连续范围中，选择最短且自然的一条。target 是
  软目标，maximum 只是上限；不得为了接近 target 或用满 maximum 延长已经完成的片段。
- first_complete_payoff_cue_id 是第一个已经把承诺完整说完的 cue。若从 start 到该 cue 已达到
  minimum，end_cue_id 必须停在这里。只有该完整范围仍短于 minimum 时，才可向后保留紧邻、
  同一 promise 的澄清或复述，并在 minimum_duration_extension_cue_ids 中逐一列出 payoff 后到
  end 的全部 cue；感谢、求赞、销售、闲聊或新话题永远不能作为这种延长。
- 若 hook 明确提出二选一、方向对照或条件对照（例如“什么时候 A、什么时候 B”），payoff
  必须说明两侧分别在什么条件下成立。只回答第一侧不算完整结论，也不能把第二侧另立为
  “不同 viewer_promise”；应在连续且不超时的前提下保留一个完整对照版本。
- topic unit 是全局目录索引，不是候选的硬边界。一个原始问题、编号框架、演示与诊断若跨过
  相邻 unit，必须跨 unit 寻找最短完整范围，并让所有被跨过的相邻 unit 共同引用该候选；不能
  因目录切分而省略问题的另一侧、前面的步骤或后面的结论。
- “最短完整”先要求兑现原片已经提出的完整承诺，再在这些完整版本中最短。不得先把
  viewer_promise 窄化成只剩一侧、后两个步骤或一个局部结论，再声称这个残缺版本最短。
- 编号方法、路线或清单若在标题或 viewer_promise 中承诺 N 项，所选连续范围必须独立提出
  全部 N 项，并包含理解这套框架所需的解释。无需回到直播中最早一次零散讲解：后文若重新
  完整列出全部项目并继续解释其关系或重点，这个重述可以成为更短、更直接的合法开头；反之，
  只在片尾快速念出名称，仍不能替代被剪掉的必要说明。
- 一个 cue 末尾开始了新问题、销售或未完成转折时，不能只引用该 cue 前半句作为干净结尾。
  若前一 cue 已完整兑现当前承诺，应结束在前一 cue；否则重新定界或放弃。
- 开头也必须做“后缀反证”：在当前区间内部向后查找直接提出同一问题、困惑、冲突或示范的
  cue。若从这个更晚的 direct 开头到合法结尾仍在 minimum–maximum 内并完整兑现 promise，
  必须使用这个更短的范围；较早的答话残片、被否定路线或对片段外谈话的承接不属于
  necessary_context。自动 selected 的 opening_relevance 必须是 direct；necessary_context 只能
  进入 manual，除非重新定界后消除依赖。

## 时长与数量

- 遵守运行时 minimum_duration_sec、target_duration_sec 和 maximum_duration_sec。目标时长
  是偏好，最短和最长是硬限制。
- 核心内容不足最短时长时，只能使用同一话题的前提、解释、演示或结论自然扩展；不能用
  噪声补足。无法自然达到最短时长时放弃。
- 准备把相邻的两个或多个 topic 分别以 duration_too_short 拒绝前，必须回到最早的真实开头
  检查它们是否其实是同一问题的不同阶段、条件、动作或对照答案。若合并后的连续范围只兑现
  一个开头承诺、自然闭合且符合时长，应返回一个跨 topic 候选；目录标签或主播口中的转场称呼
  不能覆盖原始开头已经提出的承诺范围。
- 超过最长时长时选择更小的完整子话题，不得直接切掉结论。
- Discovery 和 Global Review 均可返回零到多个结果。max_clips 只是最终上限，不得补足。

## 真实开头与核心内容

- source_opening_quote 必须逐字来自 start_cue_id 附近的原始字幕；标题和改写后的 hook 不能
  代替原视频的真实开头。
- source_closing_quote 必须逐字来自 end_cue_id 附近。ending_complete 要根据原片最后一句的
  语法和语义判断，不能根据模型生成的 payoff 或标题判断。
- start cue 的第一段实际话语就是开头。若同一 cue 先出现课程宣传、欢迎或闲聊，随后才进入
  hook，不能忽略前半 cue 并把 opening_relevance 标成 direct。
- topic_core_start_cue_id 到 topic_core_end_cue_id 必须覆盖实际兑现 viewer_promise 的核心。
  欢迎、拜拜、点赞、礼物、助播闲聊、设备调整和无关销售不得算入核心。
- opening_relevance=irrelevant、quality_flags 包含 padded_with_irrelevant_content，或核心依赖
  无关首尾内容才能达到最短时长时，内容必须放弃。
- 无关内容位于问题和结论之间且无法跳过时可以保留连续区间，但必须如实标记，且不得用它
  补足最短时长。

## 来源忠实度

- title、hook、payoff 只能压缩原片实际表达的立场，不得替主播补充批判、免责声明、反驳、
  因果或价值判断。
- title 必须能由片段中的原话立场直接支持。原片在正面宣称某种能力或效果时，不能使用
  “为何要谨慎”“真相”“误区”“靠谱吗”等措辞把它伪装成批判、质疑或事实核查。
- 平台风险说明只写入 risks 和 review_reason，不能伪装成主播在原片中表达的结论。
- 高风险或争议本身不等于普遍内容价值；原片只有主张而没有分析时，不得通过改写标题把它
  包装成科普或事实核查。

## 语义重复

- 不根据时间重叠比例或时间间隔判断重复。
- 比较 viewer_promise、解释/案例/演示和 payoff；相同结论只保留最完整、最有观看价值的
  连续版本。
- 相同 parent_topic 不等于重复。不同 viewer_promise 且各自有独立展开和结论时可以分别
  保留，即使两个片段相邻。

## 安全门槛

- 无法脱离直播理解、没有结论、混合多个无关主题、必须非连续拼接、纯欢迎/感谢/礼物/
  销售，或只有纯演唱且没有诊断/反应/回报的内容不得自动入选。
- 标出运行时 Profile 要求的健康、绝对化、商业、版权和敏感风险。不得把个人判断改写为
  医学事实或强化刻板印象。
- 风险不等于低内容价值。Discovery 仍应发现有价值的风险内容；Global Review 使用独立的
  editorial_decision 与 review_status 表达是否值得保留和是否需要人工审核。
