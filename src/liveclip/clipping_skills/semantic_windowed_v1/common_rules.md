# 通用硬规则

- 只允许原视频中一个连续 cue 区间，不跳剪、不拼接非连续内容。
- start/end、证据、核心和风险均使用输入中的全局 cue ID，时间由Python计算。
- 开头必须直接进入真实问题、冲突、示范或必要前提；标题和hook不能替代源开头。
- 结尾必须包含原文实际给出的第一个完整 payoff，不得停在未回答问题、转折或下一点。
- 核心不足45秒时只能加入同一 promise 必需的前提、解释、演示或澄清；欢迎、感谢、点赞、
  礼物、闲聊、设备、销售和听者回应不得补时。
- “最短完整”是相对于当前范围内最有普遍价值的真实承诺，不得通过把上位问题窄化成一个低价值
  半答案来获得更短边界。若一个45–90秒范围能完整回答同一问题中的两个对照条件、全部编号步骤
  或动作的前后阶段，应优先保留完整上位承诺。
- 同一话题在当前上下文出现多个局部版本时输出一个最短完整版本；不同问题各自完整时可多条。
- 问题已经由片内事实解释清楚，末句只是答案可唯一推出的确认性反问时，可以在该反问处闭合；
  不要求等待听者复述，也不要求继续加入另一轮演示。
- 问题与payoff之间无法从连续源视频移除的一两句直播互动会降低洁净度，但不等于话题不存在；
  只有把噪声放在首尾来达到minimum才属于补时并必须放弃。
- 每个候选填写真实首尾原文、opening_relevance、ending_complete、topic_core、质量标记、证据和风险。
- irrelevant_intro/outro cue IDs记录已经从候选边界剔除的相邻噪声，分别位于start之前/end之后；
  quality_flags只描述最终候选区间内部仍存在的问题。
- quality_flags使用既有枚举；无关补时、未闭合和错误立场改写不能形成候选。
- 风险不抑制发现。医学诊断、一般健康提醒、绝对化、商业、敏感和音乐版权分别标记，交由
  Global Review决定人工审核状态。
- topic_units覆盖全部输入cue。medium/high话题要关联候选，或给结构化no_candidate理由；
  风险不能成为no_candidate理由。
