# LiveClip 客户交付操作指南（双轨切分结果）

本指南写给日常操作 LiveClip 的老师或助理，不需要编程经验。照着步骤做，就能把一次
已经完成的“双轨切分”结果（短片 + 小课）导入控制台、审片、生成给客户的离线交付包，
并在**同一个局域网（Wi-Fi）**里用手机打开分享链接。

文中的 `192.168.x.y` 是占位符，请换成你自己电脑的局域网地址（第 1 步会查到）。
所有命令都在 LiveClip 项目根目录（含有 `Makefile` 的那个文件夹）里的“终端”中执行。

---

## 1. 准备

1. 打开“终端”，进入 LiveClip 项目根目录（把路径换成你自己的）：

   ```sh
   cd /path/to/autoclip-claude
   ```

2. 把这次直播的转写字幕复制到 `input/` 文件夹（只需要做一次）：

   ```sh
   cp tests/fixtures/8-30-full-transcript.srt input/8-30-full-transcript.srt
   ```

3. 查出这台 Mac 在 Wi-Fi 上的局域网地址：

   ```sh
   ipconfig getifaddr en0
   ```

   会显示类似 `192.168.x.y` 的地址；如果什么也没显示，试试 `ipconfig getifaddr en1`。
   记下这个地址，下面都会用到。

## 2. 启动控制台（终端 1）

在终端 1 里依次输入（把 `192.168.x.y` 换成第 1 步查到的地址）：

```sh
export LIVECLIP_SHARE_HOST=192.168.x.y
export LIVECLIP_SHARE_PORT=8766
export LIVECLIP_SHARE_ALLOW_LAN=true
export LIVECLIP_SHARE_BASE_URL=http://192.168.x.y:8766
make dev
```

- **这四行 `export` 只对当前这个终端窗口有效。** 每打开一个新的终端窗口（包括关掉后重新打开、
  或电脑重启之后），都要重新进入项目根目录，再把这四行重新输入一遍，然后才能运行 `make dev` 或 `make share`。
- **第一次使用这台电脑时**：如果 `make dev` 显示
  `LiveClip Python environment is missing; run make setup first` 或
  `LiveClip Web dependencies are missing; run make setup first`，先运行下面这一行（需要联网，等它自己结束），
  再重新运行 `make dev`：

  ```sh
  make setup NODE_LTS_BIN=/opt/homebrew/opt/node@22/bin
  ```

- 如果显示 `Node LTS was not found at …`（找不到 Node），先运行
  `export NODE_LTS_BIN=/opt/homebrew/opt/node@22/bin`，再运行 `make dev`。这一行同样要在每个新终端窗口里重新输入。
- 启动成功后终端会打印 `LiveClip Web: http://...`，用浏览器打开**它打印的那个地址**
  （端口可能被本机配置改过，以终端显示为准）。
- `make dev` 会一直占用这个终端窗口，不要关闭它。
- 如果看到 `LiveClip console refused to start: …`，说明上面四行设置有误（例如只设置了
  `LIVECLIP_SHARE_HOST`、地址不是局域网地址、或网址里带了 `?` 或 `#`），按提示改正后重新运行。

### 登录

- 如果浏览器显示 **登录 LiveClip** 页面（要求填写 **账号 / 密码**），用你平时使用的账号登录。
  **不要把密码写进任何文档**（包括本指南、聊天记录、截图或交接说明）。
- 如果没有出现登录页、直接进入了控制台首页，说明这台电脑还没有启用密码登录，直接继续下一步即可。
- **没有账号或忘记密码**：请联系这台电脑的 LiveClip 管理员。管理员登录后在控制台的
  **成员管理** 页面为你创建账号或重置密码。
- LiveClip **没有**用来创建账号或管理员账号的命令行命令。第一个管理员账号只能由负责这台电脑的人
  按 `README.md` 中关于“成员管理”的说明初始化：在项目根目录被 Git 忽略的 `.env.local` 文件里设置
  `LIVECLIP_BOOTSTRAP_ADMIN_PASSWORD`（12–128 个字符），重启 `make dev` 后，用
  `LIVECLIP_WORKSPACE_USERNAME` 对应的用户名（未设置时为 `local-admin`）登录。这个设置只会为还没有密码的
  管理员补上密码，不会修改已有密码。日常操作人员不需要做这一步。

## 3. 导入 cold-36 结果

1. 在控制台首页点右上角的 **导入双轨结果**。
2. 填写：
   - 结果目录（服务器本机路径）：`data/evaluations/dual-profile-benchmark-20261106-claude-cold-36`
   - 转写字幕 SRT 路径：`input/8-30-full-transcript.srt`
   - 项目名称（可选）：例如 `8-30 直播精选`
3. 点 **导入并开始审核**。导入会复制视频和字幕，大约 1 GB，需要稍等片刻；原结果不会被改动。

## 4. 审片

导入后会自动打开项目，页面分为 **短片（n）** 和 **小课（n）** 两组。

- 每张卡片可以直接播放视频；“自动入选 / 需人工审核”是模型的初步判断。
- 点 **批准**：会展开一个表单，里面已经填好了客户会看到的 **客户标题 / 高光钩子 / 内容摘要**，
  可以直接改写，改完点 **确认批准**。
- **黄色提示“疑似审核备注，请改写”**：表示这段文字里有不适合给客户看的内部说明
  （例如“疑为转写错误”“纳入后会超过时长上限”），黄色高亮的就是问题文字。请改写后再批准；
  如果确实要保留原文，需要审核人勾选 **仍然保留原文**。
- 点 **不通过**：这条不会交付。
- 勾选 **选入交付**：只有“自动入选”或已批准的切片才能勾选。若提示需要保留原文，
  只有审核人能点 **仍然保留原文并选入**；其他成员会看到“需审核人批准后才能保留原文”。

## 5. 生成离线交付包

1. 在页面下方的 **客户交付版本** 区域，填写 **交付标题（客户可见）**。
2. 确认“将包含的切片”列表无误（如有黄色提示，建议先回去改写）。
3. 点 **生成交付包**，等待状态变成 **已完成**。
4. 点 **下载 ZIP**，下载后解压。
5. 双击解压后的 `index.html`，即可在浏览器里离线观看；视频在 `clips/short`（短片）和
   `clips/lesson`（小课）文件夹里，字幕是同名的 `.srt` 文件。整个文件夹就是可以直接发给客户的交付包。
6. 若视频无法播放，请用 Chrome 打开（离线 `index.html` 目前只在 Chrome / Chromium 中验证过；
   Safari 等其他浏览器直接打开本地文件时可能无法播放）。也可以直接双击 `clips` 文件夹里的视频文件观看。

## 6. 启动分享服务（终端 2）

`make dev` 占用着终端 1，所以要**另开一个终端窗口**（终端 2），进入项目根目录后，
重新输入**完全相同**的四行设置，再启动分享服务：

```sh
cd /path/to/autoclip-claude
export LIVECLIP_SHARE_HOST=192.168.x.y
export LIVECLIP_SHARE_PORT=8766
export LIVECLIP_SHARE_ALLOW_LAN=true
export LIVECLIP_SHARE_BASE_URL=http://192.168.x.y:8766
make share
```

- 成功时会显示 `LiveClip share server on http://192.168.x.y:8766 ...`。
- 第一次启动时，macOS 可能弹出“是否允许 Python 接受传入的网络连接”，请点 **允许**，否则手机打不开。
- 如果显示 `LiveClip share server refused to start: …`，按提示修改设置
  （分享服务只能绑定本机局域网地址，不能用公网地址、`::` 或主机名）。

## 7. 创建分享链接

1. 回到控制台，在已完成的交付版本下面找到分享区域。
2. 选择 **有效期**（1 / 3 / 7 / 14 / 30 天，默认 7 天），点 **创建分享链接**。
3. 链接**只显示这一次**：马上点 **复制**，发给同一 Wi-Fi 下的客户或自己的手机；
   保存好之后点 **我已保存，隐藏链接**。
4. 下方的列表会显示每个链接的状态（有效 / 已过期 / 已撤销）、到期时间、访问和下载次数；
   不再需要时点 **撤销**。

## 8. 手机实测清单

手机连接**和电脑相同的 Wi-Fi**，然后逐项确认：

- [ ] 打开分享链接，能看到交付标题、短片 / 小课两组，以及“此分享链接将于 … 失效”的到期说明。
- [ ] 每个视频都能播放，并且可以拖动进度条。
- [ ] 能单独下载某个视频（MP4）和字幕（SRT），文件名是中文标题。
- [ ] 能点 **下载全部（ZIP）**，下载完成后能解压。
- [ ] 随便改动链接里的几个字符再打开，应显示“链接不可用”。
- [ ] 在控制台点 **撤销** 后，手机刷新页面，应显示“链接不可用”。
- [ ] 控制台的链接列表里，访问和下载次数有增加。
- [ ] （顺带检查）手机关掉 Wi-Fi、改用移动数据时打不开链接——这是正常的，分享只在局域网内有效。
- [ ] **iPhone + Safari**：在 iPhone 上用 Safari 打开分享链接（以 `http://192.168.x.y:8766/` 开头的网址，
  不是 `file://` 开头的本地文件），确认视频能播放、能拖动进度条、能下载，并把结果（能 / 不能、哪一项不行、
  iOS 版本）记录下来交给开发人员。
- [ ] （可选）**故意写错地址启动一次**：在新的终端窗口里，把 `LIVECLIP_SHARE_HOST` 故意写成没有替换的
  `192.168.x.y`（其余三行照常），运行 `make dev`，确认看到一行 `LiveClip console refused to start: …`
  提示、控制台没有启动（紧接着可能还有一行 `make: *** … Error 2`，属正常）；然后改回正确地址重新运行，
  确认能正常启动。

## 9. 安全须知

- 分享链接**只在可信的家庭或办公室局域网**使用；**不要在公共 Wi-Fi**（咖啡馆、酒店、机场等）使用。
- 传输没有加密（http），所以不要把分享端口暴露到互联网：**不要使用任何隧道或代理**
  （如 ngrok、cloudflared、`ssh -R`、路由器端口转发等）。分享服务会信任来自本机的访问，隧道会让外网绕过限制。
- 运营商共享地址（100.64.x.x，部分路由器或 Tailscale 等组网工具使用）和 IPv6 过渡地址会被故意拒绝，这是预期行为。
- 电脑的局域网地址变了（例如重新连接 Wi-Fi 后），旧链接会失效，需要重新创建。
- 不在同一局域网的客户，请直接发送第 5 步的离线 ZIP。
- 链接过期或被撤销后无法恢复，需要重新创建。

## 10. 停止服务

- 在终端 2（分享服务）按 **Ctrl+C**。
- 在终端 1（控制台）按 **Ctrl+C**，它会一并停止网页、接口和后台任务。
