Review rule

Clean master first

The review master is a clean current-revision render. Editorial title, Hook, reason, risks, and captions remain separate structured data. Optional burned title/caption media is a distinct derivative, never a silent replacement for the clean source of review truth.

!

Review truth is revision-bound. A changed boundary, caption, or EditPlan creates a new revision and stales derived renders and active package eligibility.

NO DECISION WRITE

Offline review package

File-only CSP viewer plus clean MP4, SRT, Markdown/JSON, checksums, and ZIP. It snapshots current review context but never approves a clip or substitutes for Delivery.

SELECTIVE HANDOFF

Edit package

Chosen current proxies, clean MP4/SRT, thumbnail/contact sheet, editorial metadata, guide, CSV/JSON, hashes, and ZIP for an external editor.

APPROVED SET

Formal Delivery

Only approved selected current revisions. Immutable Project-version snapshot with exact videos, SRT, titles, bounds, filenames, hashes, manifest, and ZIP.

PLATFORM HANDOFF

Release package

Exact approved media mode, selected cover, editable copy, preset checks, checklist, manifest, checksums, and ZIP. External scheduling only—LiveClip stores no social credentials and performs no upload.

03 · Parallel experimental lane

Agent v2 interprets. The harness constrains.

Experimental, non-default, and preserved beside v1. It may use real provider inference only under its own explicit run authority.

Agent runtime boundary · model output is untrusted
01 / POLICY

Skill + ordered Prompts

Versioned editorial behavior, Profile rules, stage prompts, response schemas, and tool exposure. Skill bytes are part of run identity.

02 / INPUT

Bounded Context

Transcript cues, evidence, budgets, configuration, cancellation state, and immutable source identity—not arbitrary filesystem context.

03 / TRANSPORT

Responses or App Server

Native OpenAI Responses function tools, or pinned Codex App Server transport using existing login. Transport does not gain product authority.

04 / HARNESS

Strict turn loop

Closed typed schemas, exact call IDs, bounded turns/bytes/time, cancellation, retry, cache, and provider evidence. No embedded editorial heuristics.

05 / CAPABILITY

Strict local tools

Only registered functions in agent_tools. Built-in shell, filesystem, Web, MCP, plugins, and subagents are unavailable in the App Server profile.

06 / STATE

Journal + Artifacts

Append-only events, drafts, global review, subtitle calibration, title choices, full history, pending calls, and hashes support fail-closed recovery.

07 / COMMIT

finish gate → adapter

finish is a typed function. It succeeds only with complete valid artifacts and no pending call, then hands exact cue IDs to deterministic delivery.

Transport is replaceable.Native Responses and Codex App Server produce the same correlated function-call contract; built-in authority is denied.
Full review precedes titles.Every raw candidate receives an exhaustive global-review disposition before final candidates unlock title tools and presentation.

No promotion by implication.Scripted tests, a completed inference run, technical validation, rendering, and human acceptance remain separately evidenced gates.

04 · Security model

Data crosses gates, never assumptions.

Transcript text, model content, paths, and package metadata are data to validate. None can become executable policy merely because a model emitted it.

Product trust boundaries

BoundaryRule
Source mediaRead-only reference inside configured allowed roots; source frames remain local
Transcript/modelUntrusted quoted content; strict DTO/schema validation; no instructions followed
Media executionValidated fixed argv with shell=False; model never supplies paths/filtergraphs
StorageNo-follow identity checks, streaming hash, private attempt tree, fsync, atomic no-replace publish
ServingOpaque asset IDs and authorization; no arbitrary local-path reads
SecretsIgnored local environment/private HOME only; redacted from logs, errors, receipts, manifests, and Git
