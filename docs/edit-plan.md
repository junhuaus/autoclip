# EditPlan v1

The canonical timebase is integer milliseconds from source start. EditPlan revisions are immutable; any title, time, layout, caption, effect, or caption-cue change creates a new revision and invalidates older renders.

Minimum content:

```json
{
  "schema_version": "1",
  "candidate_id": "uuid",
  "source_start_ms": 125500,
  "source_end_ms": 183200,
  "score": 88.0,
  "title": "简洁中文标题",
  "hook": "开场钩子说明",
  "reason": "推荐理由",
  "layout": "vertical_blur_background",
  "caption_template": "clean_zh_v1",
  "effect": "none",
  "risk_flags": [],
  "prompt_version": "editing_v1",
  "model": "configured-model",
  "degraded": false
}
```

Allowed v1 values:

- layout: `vertical_blur_background`, `center_crop`
- caption template: `clean_zh_v1`
- effect: `none`, `fade_in_out`

Pydantic uses strict types and `extra='forbid'`. Start is nonnegative; end is greater than start and within source duration; duration is within configured limits; an AI adjustment stays inside the candidate context window. Score and string/list lengths are bounded. No generic extension map exists. Unknown fields and any path, command, code, script, SQL, URL intended for execution, or filter string are rejected.

Captions are structured relative cues attached to the same revision:

```json
{"start_ms": 0, "end_ms": 2400, "text": "字幕文本"}
```

Cue bounds are ordered, nonnegative and no later than the clip duration. Text is normalized and rasterized locally; it never enters executable FFmpeg syntax.

The generated JSON Schema is checked into the release artifacts or generated by a documented command and contract-tested against the OpenAI wire model. Provider parsing is followed by independent domain validation. A repair call is allowed once for a normal invalid structure; then the system creates a deterministic plan with `degraded=true`.
